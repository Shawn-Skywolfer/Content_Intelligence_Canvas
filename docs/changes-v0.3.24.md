# v0.3.24 全局代理、独立网页工具与可诊断错误

## 网络配置流程

1. 设置 → 全局网络与代理：选择自动、直连、系统代理或企业代理，保存后对所有选择“继承全局网络设置”的服务生效。
2. 模型、搜索 MCP、DeepSeek 网页工具可以各自覆盖全局配置，使用独立代理与凭据。独立配置不会借用全局代理的账号密码。
3. 首次升级时，原自动连接配置转为继承全局；已有明确的直连、系统代理、企业代理保持原设置。之后手动选择的单独自动检测保持独立。
4. 全局网络测试只验证能否收到 HTTP 响应；模型调用、搜索、抓取的可用性仍使用各自的功能测试。
5. 一键导出和导入包含全局代理、各服务覆盖和密钥，旧版设置备份仍可导入。

## 搜索与抓取流程

- Search 和 Fetch 分别启用、关闭和测试，结果各自保留。可以同时监测两个独立测试。
- 搜索开启时优先 DeepSeek，否则使用搜索 MCP；只开启 Fetch 时，可以给 MCP 找到的链接补读全文，也可单独测试指定网址。
- Fetch 关闭时不会发起抓取请求；Search 已返回的正文可使用，缺少正文的网页明确跳过。全部缺少正文则失败，不用摘要代替全文。
- 默认检索语法支持 `site:`、`-site:`、排除词、精确短语、`lang:`、`after:`、`before:` 与 `OR`，完整追加到任务搜索词后。总查询受 128 字符限制，优先保留语法；测试和日志显示实际发出的查询。
- 可设置搜索本地化 IP。Fetch 按官方接口接收 HTTP(S) 网页地址，不使用搜索操作符。
- 正文保持完整，不以固定字符数截断；完整流程测试展示正文数量、字符数、来源与预览。

## 错误与任务诊断

- 失败返回结构化的 operation、http_status、reason、suggestion、endpoint、retryable。
- 400、401、402、403、404、408、413、429、5xx 等保留实际 HTTP 状态，并提供中文原因和处理建议。不会把供应商原始响应中可能出现的密钥带到界面。
- HTTP 200 但缺少可用正文/结果同样明确标为功能失败，区分接口接收成功与内容可用。
- 未取得 HTTP 响应时状态为空，显示“未收到 HTTP 响应”，不伪造供应商状态码。
- 异步测试轮询的 HTTP 200 仅代表任务查询成功；实际上游错误保存在 failure 字段。白板 AI 任务失败详情会持久化并显示这些信息。
- 同步加工 API 的错误响应保留上游错误状态；HTTP 200 但内容不可用等异常使用本地 502，detail 保留实际上游状态。
