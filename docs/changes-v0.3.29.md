# v0.3.29：完整响应与草稿交付

新日志表明第一版正文已收到完整结果，后续简报审阅要求自动修订，最后日志停在修订正文接收阶段。不能据此断言供应商已发送完整修订结果。

- 新建与已有模型默认使用完整响应请求；设置可开启“流式接收（实验）”，保留实时推理能力。
- 完整响应接收放入独立线程，监督线程支持取消与单次调用总时限（配置超时的两倍加 15 秒，最短 30 秒、最长 600 秒），避免关闭连接阻塞而无限等待。
- 内容输出及共创在简报审阅前保存完整草稿，修订完整返回后更新检查点，审阅或修订失败仍保留。任务运行中即可打开详情查看已完成草稿。
- 草稿未通过核对时明确标识，不冒充定稿、不自动存为内容资产。

测试使用受控响应，覆盖默认完整请求、显式流式请求、简报修订失败后 SQLite 中保留完整草稿。用户供应商、代理及真实 Wiki 环境尚待复测，根因仍未唯一确认。
