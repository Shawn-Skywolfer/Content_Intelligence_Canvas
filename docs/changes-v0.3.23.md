# v0.3.23 启动稳定性与网页正文上下文

## 本地启动

- 启动器串行处理多次点击，避免并发解包覆盖；只按本应用路径、PID 与进程创建时间替换旧实例。
- 优先使用 Windows 系统 tar 解包；备用 PowerShell 通过环境变量接收路径并启用严格错误处理，不再将路径拼进脚本。
- 解包到临时运行环境，关键文件完整后才提交和写就绪标记；缺损缓存自动修复，Python 提前退出时自动重建重试一次。
- 增加启动提示与日志；第三方依赖加载放入可记录错误的启动流程，避免 pythonw 静默退出。
- 本地健康检查显式绕过所有代理，服务就绪后由启动器打开浏览器；绑定监听套接字后交给服务器，避免先找空端口再绑定的竞态。
- 优先使用现有随身数据目录；若 EXE 换了位置且新位置没有数据，复用上次已有数据库的目录，避免误认为配置或 Key 丢失。
- 启动失败时提示日志位置：本地应用缓存目录中的 launcher.log、startup-python.log、startup-status.json。

## 网页内容流程

1. 节点勾选网络检索后，优先用已启用且有 Key 的 DeepSeek。
2. Search 始终请求正文。搜索结果已返回正文时直接使用，减少重复网络请求。
3. 缺少正文的网页自动调用 Fetch；不再只处理前两条，旧版抓取条数和截断长度设置不限制此流程。
4. 无法取得正文的网页跳过并显示原因；所有网页都不可读时明确失败，不用摘要代替，也不切换 MCP 摘要冒充 DeepSeek 全文。
5. 网页正文按服务实际返回内容完整交给模型，不再按 8000 字符截断。模型自己的上下文长度限制仍适用。
6. 任务显示正文页数和字符数；生成节点的网络来源区可查看实际用于上下文的正文。
7. 设置页以“保存并测试完整联网流程”为主操作，显示实际取得的正文数量、长度和预览，接口单项排错保留在折叠区。
8. DeepSeek 未启用时仍可使用现有搜索 MCP；408、429、5xx 暂时错误只重试一次，取消任务不重试或回退。

## 验证

- 前后端回归，包含企业代理不影响本地健康检查、移动 EXE 后数据复用、正文末尾超过 8000 字符仍进入模型。
- 浏览器真实完整联网测试：两篇正文共 13288 字符，约 13.8 秒。
- 真实模型全流程：DeepSeek 搜索、取得两篇正文共 10873 字符、交给 deepseek-flash、生成带来源的新笔记节点，约 21 秒。
- Windows CI 使用中文和单引号目录、无效环境代理，验证冷启动、热启动、缺损缓存修复、连续双击、旧进程替换及数据保留。

以上为已定位代码路径的修复；用户机器若仍启动失败，可根据新版日志定位具体环境问题。
