# v0.3.32：任务停滞与界面整理

## 日志结论

本次日志中，任务三次停在 Wiki 规划阶段。一次首轮规划已收到 HTTP 200 和有效 JSON，输入约 5.4 万 token；随后关系规划再次调用模型，长时间没有后续活动。日志没有显示已开始网页搜索，也没有服务端报错，因此不能据此认定是网页抓取失败、模型完全不可用或触发网络风控。旧日志没有应用版本及足够的线程诊断，无法唯一确认具体阻塞位置。

## 修复

- 首轮仍完整读取 overview.md、domain-map.md。检索规划独立使用 2048 token 输出预算，关闭支持该参数的 DeepSeek 思考模式，总时限 75 秒。
- 关系规划只发送问题、首轮计划和 relations.md，避免重复发送完整总览；总时限 60 秒。超时或连接失败时沿用已经完成的模型计划，继续读取原始 Wiki。鉴权错误、无效结构和取消不会被静默忽略。
- 普通响应在 TLS 清理前交付已接收的完整正文；网络请求及 JSON 解析均在受监督线程中执行。日志队列有容量限制，日志写入卡住不阻塞正文交付。超时只取消本次调用，不污染可以恢复的父任务。
- 白板任务另有独立保护：连续 180 秒没有阶段或模型活动，或执行超过 60 分钟，终止等待并保存失败状态、现有草稿和线程位置。用户可查看详情、导出日志、修改要求并重试；不自动重复付费请求。
- LOG 新增应用版本、调用 ID、阶段、输入字符数、输出预算、请求时限与线路；超时包含代码位置，不记录线程局部变量。任务详情中可展开调用诊断。

## 页面流程

项目输入主题 → 快速研究填写问题与简报 → 选择知识源与数量 → 白板查看来源、编辑及 AI 共创 → 确认输出节点 → 保存、管理和导出内容资产。缺少知识源时提供直接添加入口。

移除重复标题、标语、说明卡片及大段常驻帮助。统一页面宽度、左对齐和表单间距；快速研究改为单栏，模型高级选项默认折叠。必要帮助使用支持鼠标、键盘聚焦和 Escape 关闭的提示，不挤占表单；设置标签支持方向键、Home、End。真实进度、错误、导出密钥提示及删除后果仍明确显示。保留中英双语和按节点保存的 Prompt。
