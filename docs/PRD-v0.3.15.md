# 内容智能白板 v0.3.15 功能增补

## 白板 AI 加工与任务监测

1. 在白板选择一个或多个节点；分组会展开为成员节点。处理要求填写自由 Prompt，选择新节点类型。内容输出可选择在设置中定义的输出形态、正向 Prompt 和负向 Prompt。
2. 点击“AI 加工并生成下游节点”后，服务器为这组来源节点创建独立任务。当前画布可继续编辑，可以切换其他节点并启动其他任务；同一组来源节点不能重复提交运行中的任务。
3. 白板顶部常驻任务监测栏显示运行中数量、来源节点、阶段、进度、失败原因以及完成后的“定位结果”。切换节点或刷新浏览器后从本地数据库重新获取任务；应用进程重启会将未完成任务标记为中断，不会永久显示运行中。
4. 完成时创建新的下游节点，保留原节点、来源 ID、有向连线、继承的上游和 Wiki 证据。保存内容输出节点后在项目内容资产中管理。
5. 移除“形成内容概念”“生成新内容”两个重复入口及固定的“快速加工”按钮；统一在上述加工区域自定义要求。

## 搜索 MCP 与洞察

1. 设置页面采用“知识源”“大模型与代理”“搜索 MCP”“内容形态”“数据保护”五个标签页。
2. 在“搜索 MCP”配置服务名称、Streamable HTTP 地址、搜索工具名称、密钥和网络连接方式；保存后测试连接，展示服务端返回的工具名。支持 Tavily 的远程服务、兼容的 HTTP MCP 搜索服务及新版无会话协议。自定义企业代理可独立配置；密钥与代理密码写入本机密钥文件，普通配置接口不会回传。
3. 选择“洞察”节点类型时可勾选“检索网络资料”。模型先理解原节点与 Wiki 上下文，服务器通过所配置的 MCP 搜索，再把 Wiki 证据与带 URL 的网络资料交给模型综合。新节点详情分别展示 Wiki 证据和网络来源。
4. 若搜索服务未启用、连接失败、工具不可用或结果没有可引用 URL，任务显示失败与原因；不以凭空生成结果替代网络资料。

## 验收

- A 节点生成中，切换 B 节点仍可提交；状态栏同时显示两个任务。
- 浏览器刷新后仍能恢复任务和进度；生成完成可定位结果，服务进程重启后旧任务明确显示中断。
- 洞察启用网络检索后，模型输入同时含 Wiki 证据和 MCP 搜索来源；生成节点保留 URL。
- 设置标签切换不丢当前表单状态；密钥不出现在配置 GET 返回、数据库或公开 Release 中。
- Windows GitHub Actions 运行前后端测试、单体 EXE 启动与旧实例替换验证后发布。
