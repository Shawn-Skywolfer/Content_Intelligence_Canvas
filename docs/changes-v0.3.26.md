# v0.3.26：输出上限、任务诊断和视频时长

## 模型配置

所有供应商的最大可填写输出上限统一为 **384K = 393216 token**，前端、API 校验及配置导入一致。保留已有配置选定的数值与新配置的 3000 默认值，不强制每次输出 384K。实际可用长度仍由具体模型及供应商决定，界面提供说明。

依据：DeepSeek 官方 Chat Completions API `max_tokens` 文档：<https://api-docs.deepseek.com/api/create-chat-completion/>。

## AI 任务监测与删除

- 运行中：删除按钮禁用，后端原子检查状态并返回 HTTP 409，要求先暂停或取消。
- 已暂停、失败、已取消、已完成：可单个删除或批量删除选中任务。批量操作跳过运行中的任务。
- 删除仅清理任务记录和关联日志，保留生成的白板节点、连线与内容资产。
- 删除、重试和旧线程回报有状态及执行次数校验，防止过期结果写入。

## 实时状态与 LOG

监测任务的模型调用使用真实 SSE 流式响应，实时显示：

1. 应用阶段：Wiki 检索、回读原文、网络搜索/抓取、综合生成、简报核对等。
2. 模型调用：连接线路、模型 ID、HTTP 状态、本次调用耗时、供应商推理文本、推理阶段及已接收推理字符数、正文接收字符数、正文预览、结束原因及供应商返回的用量统计。
3. 等待反馈：每 5 秒写入一次等待/接收心跳；正常流式进度每秒最多保存一次，阶段切换立即记录。百分比表示应用阶段，不伪造模型完成比例。
4. 错误：保留实际 HTTP 及供应商说明，针对鉴权、权限、模型 ID、参数、额度、网络/代理等提供排错提示；断流及输出达到长度上限时明确失败，不创建不完整的输出节点。

仅展示本任务所选模型 API 实际返回的 `reasoning_content` / `reasoning` 推理文本，明确标注供应商来源，不生成或推测。界面实时查看，完整文本按增量写入 LOG，重试后保留历次记录；不返回推理字段的模型明确提示并继续接收正文。供应商明确表示不支持流式调用时，自动回退普通调用，显示等待状态和限制说明。

每个任务的完整 LOG 持久化在本地数据库中，包含创建、各阶段、网络、模型响应、错误、暂停、取消、重试及应用重启中断记录。详情页显示最近 200 条，**文本与 JSON 导出包含全部记录及历次执行**。旧版本仅保留的历史日志会自动迁移，无法恢复旧版本已经丢弃的记录。导出包含本任务 Prompt 等诊断上下文，但隐藏 API Key、Bearer、URL 代理凭据与常见敏感查询参数。

使用流程：白板下方展开“AI 任务监测” → “查看详情” → 查看“实时执行 LOG”或点击“导出 LOG（文本 / JSON）”。删除前可先导出日志。

## 视频脚本目标时长

数字框采用文本草稿保存输入状态，允许清空，输入新时长后不会补上前导零。提交时校验 15–600 秒整数，再转换为数值传给 API；切换输出形态或节点保留独立草稿。
