# v0.3.22 DeepSeek 网页搜索与抓取

## 设置与操作流程

1. 打开“设置 → MCP 与网页搜索”，现有 Tavily / 通用搜索 MCP 仍然保留。
2. 在“DeepSeek 网页搜索与抓取”中启用服务并填写 DeepSeek API Key。接口默认 https://api.deepseek.com，直接使用官方 Search/Fetch API，无需 MCP 地址。
3. 可配置搜索结果条数（1–50）、搜索是否返回正文、自动抓取前几条（0–5）、每页进入模型的最大字符数，以及超时、系统代理或企业手动代理。
4. 保存配置，或点击“保存并测试搜索”“保存并测试抓取”“保存并测试搜索和抓取”。测试前保存当前表单，测试区显示实时日志、HTTP 状态、实际网络线路、耗时、搜索结果和 Markdown 正文预览。HTTP 200 但无结果/无正文会明确失败；Search 成功而 Fetch 失败时保留分项结果。
5. 在洞察、质疑、创意模式、笔记的 AI 共创中勾选网络检索。系统自动检测：已启用且有密钥的 DeepSeek 优先，否则使用已启用的搜索 MCP；两者均不可用时明确报错。
6. DeepSeek 整体搜索失败时，如有已启用 MCP，会记录原因后回退；单页抓取失败则沿用该页搜索正文或摘要。用户取消任务时不触发回退。
7. Wiki 材料和网络资料共同交给模型加工，生成下游节点保留网络来源。任务进度显示所选服务和正在抓取的网页。

## 配置与兼容

- Key 和代理密码保存到本地密钥文件，常规配置读取不回显，代码和公开 EXE 不内置用户密钥。
- 一键配置导出/导入包含 DeepSeek 设置及密钥；旧版备份仍可导入。
- 原有搜索 MCP 配置、白板布局、AI 任务管理和用户数据继续沿用。

## 验证结果

- 用户授权 Key 的真实调用：Search HTTP 200，返回 2 条结果；Fetch HTTP 200，返回 6,402 字符正文。
- 浏览器完整验证：设置表单保存 → 真实 Search/Fetch → 分项结果与预览，共约 14.5 秒；读取配置不回显密钥。
- 两种服务同时配置的真实自动选择测试：优先 DeepSeek，自动抓取首条网页，返回 2 条来源，首条正文按配置保留 8,000 字符，约 17.1 秒。
- 前端 28 项测试及生产构建；后端全量回归（含优先级、回退、取消、HTTP 错误、空正文、四种节点联合输入模型、密钥保护与备份恢复）。
- Windows CI 验证 EXE 启动、本地接口与旧实例替换后发布。
