# v0.3.25 原始 Wiki 回读与内容约束

## 1. 快速研究数量

- 默认 20 条、可设置 3–20 条；清空数字框时不会出现固定在首位的 0。
- 显示数量范围、预计耗时关系，以及“证据不足时少于目标数量、不凑数”的提示。三条内容方向另计。
- 研究材料窗口扩大至 30 个候选引用，修复上限提高后仍只能引用前 16 个候选的问题。
- 验证连续两次各生成 20 条研究发现，三列及每列两子列不遮挡；新追加节点统一尺寸，已有用户布局不重排。

## 2. 知识库路径

- 路径示例按正常 Windows 单反斜杠显示。
- Windows 原生目录选择通过独立 UTF-8 JSON 文件传递结果，PowerShell 控制台警告不会成为路径。
- 中文、空格、单引号、UNC 目录及粘贴警告文本均有对应处理；取消选择不会采纳控制台中的任何内容。
- 前端在粘贴、失焦、提交和目录选择返回时清理路径，后端再次校验；保存过的警告前缀路径在列出及刷新前可自动修复，保留知识源 ID。

## 3. 下游生成回读原始 Wiki

1. 按用户选定的上游层级获取节点正文。
2. 沿这些节点记录的加工来源追溯原始引用，兼容跨多个中间节点、循环来源和旧版本元数据；不读取其他项目的节点。
3. 检索规划结合本次要求、项目简报和节点实际内容，避免只输入“润色”时丢失主题。
4. 通过 chunk ID 定位知识源与文件；索引刷新后 chunk ID 过期时，可用知识源 ID 和相对路径恢复。
5. 回读对应完整 Markdown 词条，按知识源和文件去重，不按 1800/8000 字符截断。多个知识库中同名文件分别保留，无法确认来源时明确报错。
6. 新增检索没有命中时，已有原始引用仍可供生成使用；模型连接错误、引用文件缺失、来源停用等错误不会被摘要掩盖。
7. 将原始词条全文、选中及上游节点正文、简报一同传入生成模型。进度显示回读篇数和字符数，生成节点记录实际原文清单和稳定引用。
8. 节点详情和全文弹窗中均可点击“查看完整 Wiki 原始词条”，直接核对当前原文。

原文全文会占用模型上下文额度；超出供应商额度时明确失败，不静默截断成摘要。一次任务内重复读取使用缓存，下次任务重新读取当前文件。

## 4. Markdown 显示

- 节点全文、任务详情和内容资产统一使用 Markdown/GFM 渲染。
- 支持表格、粗体、删除线、任务列表、嵌套列表、引用、链接、代码块与脚注。
- 表格有列头、单元格间隔和横向滚动；长代码独立滚动；全文弹窗加宽并保留关闭按钮。
- 原文仍可直接输入和编辑 Markdown，不改变已保存的正文。

## 5. 简报的约束优先级

- 研究、普通共创、概念、当前节点加工和最终内容输出均显式读取项目内容简报，不依赖是否连线、是否选中简报节点或上游深度。
- 简报中的受众、目标、形式、语气、禁止事项等为默认硬约束；一般的“润色”“改写”或形态模板不构成覆盖授权。
- 只有本次要求明确指出覆盖某个简报条款时，该条款才例外，其他条款继续有效。
- 事实真实性与证据边界不允许通过简报或加工要求覆盖。Wiki 正文和普通节点正文是资料，不能修改以上规则。
- 生成后进行独立模型核对；常见字数上限和指定开头另由程序检查。违反约束时用同一份完整原始资料自动修订一次，再复核；仍不通过则明确失败，不创建节点或资产。
- 任务进度显示核对、自动修订与复核阶段；这会增加一次核对调用，修订时还会增加调用与耗时。
- 每次生成保存本次实际使用的简报快照和核对结果，后续任务采用更新后的简报。

## DeepSeek 调用稳定性

- 修复“关闭思考模式”对 DeepSeek 实际未传递关闭参数的问题，避免默认思考消耗输出额度却没有正文。
- 若推理或输出额度耗尽，明确提示提高最大输出 token 或关闭思考，不再只返回“空内容”。
